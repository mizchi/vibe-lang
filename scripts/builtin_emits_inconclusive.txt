# Probes that answer with neither a finding nor a clean compile
# (scripts/check_builtin_emits.sh). Inconclusive is UNCHECKED, not safe, so
# each one is named here rather than absorbed into a count.
#
# SHRINK-ONLY: the gate fails both on a name that becomes inconclusive without
# being listed, and on a listed name the probe has learned to answer for. Most
# of these are the probe's limits, not the compiler's -- teaching it to spell
# them is the way to remove a row.
#
# The receiver-typed operators. `T` -> `Int` is the wrong guess for these
# three: they are type-directed in checker.vibe and want an Array / String /
# Bytes receiver ("slice receiver must be String, Bytes, or Array, got Int").
# A receiver-aware substitution would answer for them.
__index
__len
__slice
#
# `declare Path::to_string(Path)` names a type nothing can spell -- "unknown
# type `Path` in parameter". Arguably a defect in the declaration rather than
# in the probe.
Path::to_string
Path::is_absolute
#
# "effectful call outside effectful context" -- a SECOND message shape the
# row-retry does not recognise (it only knows "no 'with' clause, requires
# { R }", which does not name the row here). Teaching it this shape would
# answer for all four.
sleep
StdinStream::next
StdinStream::close
StdinStream::read_chunk
#
# Genuinely not probeable this way: "requires an Async component entry named
# run; standalone core/library and non-Async entries cannot provide it". A
# one-function probe is not a component.
Stdin::read_via_stream
