# Library definitions that share a name with a builtin (see
# scripts/check_builtin_shadowing.sh).
#
# The SCOPE of such a definition depends on the name's shape. Measured
# 2026-08-28 on stage2 of 3725175, four names, each called both from its own
# file and from an importer that imports only an unrelated name:
#
#   String::index_of  qualified   importer got the local definition
#   String::trim      qualified   importer got the local definition
#   eq                bare        importer got the BUILTIN
#   not               bare        importer got the BUILTIN
#
# So a QUALIFIED (`X::y`) definition replaces the builtin for the whole linked
# program, and a bare one is contained to its own file. Only the qualified rows
# below can surprise a dependent; the bare ones are listed because the
# containment is an observed property of today's resolver, not a stated rule.
#
# Entries may be REMOVED, never added. Removing one means either the function
# was deleted (the builtin answers) or it was renamed to something the registry
# does not own.
#
# <path> <name>

# --- qualified: program-wide ---
# Both were measured equivalent to their builtins (20/20 answers, including
# tab/LF/CR/VT/FF padding and the equality edge cases) and performance-neutral
# (trim and equals both within noise of the builtin), so they are kept rather
# than deleted along with the six scalar search re-implementations.
lib/@vibe/builtin/string.vibe String::equals
lib/@vibe/builtin/string.vibe String::trim

# --- bare: file-local ---
lib/@vibe/cache/cache.vibe __compact_fingerprint_hash
lib/@vibe/compiler/core/polyfill.vibe __to_string
lib/@vibe/compiler/entry/compiler/fs_compile/closure_order.vibe resolve_path
lib/@vibe/console/io.vibe print
lib/@vibe/console/io.vibe println
lib/@vibe/module/path.vibe resolve_path
lib/@vibe/parser/polyfill.vibe __to_string
lib/@vibe/semver/semver.vibe eq
lib/@vibex/shell/commands.vibe print
lib/@vibex/shell/commands.vibe println
