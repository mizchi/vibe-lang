## 凡例

| 0060 | **可変性を「領域つき書き込み capability」で統一する設計 (#629)**。局所 `let mut`（ADR-0017）と跨スコープ mutation（`effect Mut`/`Emit` + handler、ADR-0021）を、Koka の `st<h>`/ML region 推論と同型の **領域 (region) でパラメータ化した書き込みエフェクト** `Write[r]` の一機構で説明する統一モデルを採る。線引き: (1) **局所 `let mut x`** = 「新しい領域 `r0` を導入し、その `Write[r0]` ハンドラを束縛点で即設置・即 discharge する」糖衣 — `Write[r0]` はブロック内で完全消化されるので **関数の公開エフェクト行に漏れない**。「権限なしのローカル書き換え」は権限が*不要*なのではなく**権限がブロックに閉じている**から許される、と一貫説明できる（ADR-0017 の「escape 不可」= region `r0` が束縛点を scope-out すると無効、という region 規律で正当化）。(2) **外側 mut を書き換える関数**は領域権限を公開行 `... with { Write[router] }` に宣言し、ハンドラ設置者（mut 所有側）だけが grant する。権限を持たない関数は行に `Write[r]` が無く型レベルで書込不能。(3) **アンビエント状態**（host/global）は `#import` 付き外部エフェクト（`archive/mut-effect-plan.md` Phase 2）としてビルトインが grant。#418（ADR-0052 mut field の escape 検査）の escape ルールは region 規律として再定式化する（`mut` field を持つ struct への参照が関数戻り値・クロージャ捕捉・async/spawn 越しに保持されることの検査 = 領域 `r` が所有スコープを脱出していないことの検査）。理論的裏付け: モデル本体は Koka region 効果、escape 制御は Effekt の second-class capability（*Effects as Capabilities*, OOPSLA'20 / *From Capabilities to Regions*, OOPSLA'23）と同型。前提 #626（effect 変数の真の単一化・effect row 正規化）は解決済み (closed 2026-06-27)。本 ADR は採用方針の記録であり、`Write[r]` の脱糖・region 推論・escape 再定式化の実装は後続作業。**実測による重要な留保 (2026-06-29)**: 現行ランタイムは `let mut` セルを capture 時に heap-box し、**クロージャ捕捉で束縛ブロックを escape しても健全に動く**（escape したカウンタが状態を保持、複数クロージャが 1 セルを共有）ことを selfhost compiler 実機で確認した。つまり `let mut` は既に ML `ref` / JS closure 相当の「共有・indefinite extent な可変セル」であり、ADR-0017 の「escape 不可」は**未強制かつ実装と矛盾**する。よって本モデルの「`Write[r0]` は束縛ブロックで即 discharge され region を脱出しない」は **非 escape の mut にのみ成立**し、捕捉された mut の region は**捕捉クロージャの寿命まで延びる**（Koka/Effekt の second-class 制約のように lexical escape を一律禁止すると動作中の機能を退行させるため採らない）。実装着手前にこの整合が前提。詳細は #629 / #418 / `archive/mut-effect-plan.md`。 | proposed |
