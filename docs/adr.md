# Architecture Decision Log

軽量な意思決定レコード。各エントリは「何を決めたか」だけを記録する。
詳細な経緯が必要な場合は git log や issue を参照。

細粒度の locked decisions は [spec/decisions.md](spec/decisions.md) を参照。

---

## 凡例

- **accepted** — 採用済み・実装済み
- **partial** — 一部のみ実装済み。**どこまで着地したかは本文に明記する**
- **proposed** — 方針決定済み・未実装または実装中
- **deferred** — 延期
- **superseded** — 後続の決定で置き換え済み

## Rules for this log

New entries are written in English (AGENTS.md "Language and documentation
policy"); the existing Japanese rows migrate as they are revised.

**An ADR number is permanent and unique.** Numbers are cited from source
comments, fixtures, gate scripts, and other ADRs, so each must resolve to
exactly one decision. Never reuse a number, and **never start a per-section
number series** — the sections are a reading aid, not separate registries.
Until the 2026-08 cleanup the Tooling section ran its own series and collided
with Core on 0049 / 0050 / 0052 / 0053 / 0075; the two live entries were
renumbered to 0103 / 0104 and the three whose subject no longer exists were
deleted.

**Delete an entry whose subject no longer exists in the tree.** An ADR about a
removed script, flag, or toolchain does not become history by sitting here — it
becomes a false statement about the current build.

**`superseded` is a pointer, not an entry.** Keep the row only while the
decision is still cited as the road not taken (ADR-0060 is the live example).
Otherwise fold what still holds into the successor, mark it `(supersedes
NNNN)`, and delete the old row.

**Paths in older rows may point into the retired MoonBit host.** `src/**` and
any `.mbt` / `.mbti` file went away with that host (#594). Those citations are
kept as the historical record of where a decision landed at the time — they are
not navigation, and `scripts/check_doc_path_citations.sh` exempts them for that
reason. To find the code today, use `vibe symbols` / `vibe grep` rather than a
path written down years of commits ago.

**`proposed` says what would make it `accepted`.** A `proposed` entry that has
not moved in a release cycle is a decision nobody made: delete the row and keep
the idea in an issue, where triage can reach it.

| 0110 | **Pipeline combinators are constructor-polymorphic over `F[_]` and pipeline-first (#2269, #2335–#2338).** A kinded type parameter may stand in constructor position (`F[A]`), applied constructor types unify (`F := Array`), and parameterized traits carry constructor-indexed witnesses. The canonical public surface is `import @vibe/builtin { trait Mappable }` followed by `xs |> Mappable::map(f)`: importing a trait also makes its namespaced operations visible, while trait operations never leak bare top-level functions. This is the general rule for every method-bearing trait, not a special case for `Mappable`: inherited methods are available through the subtrait namespace, and generated `Trait::operation` names are reserved against conflicting source declarations. `Mappable[Array]` lowers to eager `Array::map`, `Mappable[Option]` preserves `None` and maps `Some`, and `Mappable[AsyncIter]` preserves the pull layer. This source-level abstraction does not replace ADR-0099's two execution layers; Array remains eager and pull `AsyncIter` remains a separate layer. Package contracts preserve constructor arity, cross-module calls select the same witnesses as single-file calls, and missing or duplicate constructor implementations are checker diagnostics before code generation. Linear and wasm-gc fixtures pin both implementations and pipeline chaining. | accepted |
| 0105 | **Int is 63-bit; overflow wraps as 63-bit two's complement on every backend (#1877, supersedes archived ADR-0006's 62-bit range)**. The same in-range operands used to produce different values per backend with no diagnostic: untagged lanes (bump, wasm-gc) wrapped where i64 overflows (64-bit), while the RC lane's tagged `n<<1` wrapped `+`/`-` at 63 bits but `*` at 62 (its untag shift ran after the multiply) — silent-wrong, and even ops within one lane disagreed. ADR-0006's range (-2^61..2^61-1) assumed 2 tag bits; the shipped representation uses 1, so the honest width is 63. Decision: (1) Int's range is **-2^62 .. 2^62-1**, the literal bound moves to 2^62-1, and `+` `-` `*` `/` `<<` unary-minus wrap by sign-extending from bit 62 — identical values on bump / RC / wasm-gc. (2) The width follows the representation, so the RC (production default) lane wraps for FREE — its only change is untagging the multiplicand BEFORE the multiply ((t>>1)*u, same instruction count); untagged lanes renormalize with 2 branch-free instructions after the five ops (`%`/`>>`/bitops are closed over in-range values), and chain-INTERIOR renorms are elided — a result feeding another wrapping op skips its renorm, since the renorm rewrites only bit 63 and wrapping ops derive result bits 0..62 from operand bits 0..62 alone, so only the chain's outermost renorm runs and per-op observed values are unchanged. (3) Trap-on-overflow was rejected (per-op cost, and wrapping is what hash/PRNG code wants); normalize-at-binding was rejected (breaks referential transparency: `let t = a*b; t/c` would differ from `a*b/c`). Pinned by `lib/@vibe/compiler/tests/int_overflow_wrap_test.vibe` (all lanes) and the per-PR linear-vs-gc parity guard `bench/exec/int_wrap.vibe`. Until the next bootstrap bump the committed seed still enforces the old literal bound and seed-driven tooling lexes `lib/**`, so large constants there are spelled by arithmetic (`(2305843009213693951 << 1) | 1`). | accepted |
