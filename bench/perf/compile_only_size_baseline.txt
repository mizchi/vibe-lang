# Compile-only size budget (#2506), read by scripts/check_compile_only_size.sh.
#
# WHAT IS BUDGETED. The compile-only artifact (scripts/build_compile_only.sh,
# DCE-rooted at main_compile_only) may be at most
#     CLI stage2 bytes - separation_bytes * (100 - tolerance_pct) / 100
# where the CLI stage2 is the one built from the same source, and both sizes
# are taken with the name section removed. Equivalently: what the
# compile-only entry leaves out of the full CLI must not shrink by more than
# tolerance_pct.
#
# WHY NOT AN ABSOLUTE CAP. The compiler grows legitimately: stage1 built from
# main be778cd15 is 5,752,094 B against 5,593,114 B for the seed built from
# c3272d19, +2.8% across ~100 commits in four days. Capping the compile-only
# bytes would fight that the way #1109-4 records for the CLI. Compiler growth
# lands in both artifacts and cancels out of the separation; growth only the
# CLI carries widens it. So the full CLI stays observation-only, and what
# fails is code the CLI carries becoming reachable from main_compile_only.
# The absolute numbers are printed on every run and tracked, not capped.
#
# NOT YET OMITTED, so not credited here: compiler_fmt (~43 KB) and lsp
# (~24 KB) are still reachable from main_compile_only (#2499 / #2504). When
# their exclusion lands the separation grows and the gate says to ratchet up.
#
